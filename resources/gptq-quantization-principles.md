# GPTQ 模型量化原理通俗解释

> 本文整理自对 Datawhale Base LLM「模型量化」章节的学习讨论，重点解释 GPTQ 如何用校准数据和二阶信息补偿权重量化误差。  
> 参考资料：[Base LLM 模型量化章节](https://raw.githubusercontent.com/datawhalechina/base-llm/main/docs/chapter13/01_quantization.md)、[GPTQ 论文](https://arxiv.org/abs/2210.17323)

## 1. 模型量化在做什么

大语言模型的参数通常使用 `FP16`、`BF16` 或 `FP32` 保存。模型越大，权重占用的显存越高。模型量化就是把高精度权重压缩成更低 bit 的表示，例如 `INT8`、`INT4`。

一个简单的量化过程可以写成：

```text
真实浮点数 x
-> 根据 scale / zero_point 映射成低 bit 整数 q
-> 推理时再近似还原为 x_hat
```

常见公式是：

```text
q = round(x / scale) + zero_point
x_hat = scale * (q - zero_point)
```

低 bit 表示的数值范围有限，所以量化一定会引入误差。真正困难的地方不是“四舍五入”，而是：

```text
哪些权重量化错一点没关系？
哪些权重量化错一点会严重影响模型输出？
量化产生的误差能不能被其他权重补回来？
```

GPTQ 解决的就是这个问题。

## 2. GPTQ 的核心思想

GPTQ 是一种训练后量化方法，即 `Post-Training Quantization, PTQ`。它不重新训练模型，不需要数据标签，只需要拿一小批文本跑一遍模型，收集每一层的输入激活。

一个线性层原本做的是：

```text
Y = X W^T
```

其中：

- `W` 是当前线性层的权重。
- `X` 是当前线性层收到的输入激活。
- `Y` 是当前线性层输出。

GPTQ 的目标不是让每个量化后的权重都尽量接近原始权重，而是让整个线性层的输出尽量接近原模型：

```text
原输出:    X W^T
量化输出:  X Wq^T
目标:      X W^T 和 X Wq^T 尽量接近
```

所以 GPTQ 的关键思想可以概括为：

```text
普通量化：每个权重各管各的，四舍五入完就结束。
GPTQ：量化一个权重后，估计它对整体输出造成的影响，
      再调整后面还没量化的权重，把这个影响尽量补回来。
```

## 3. 什么是“用二阶信息补偿误差”

“二阶信息”听起来抽象，可以把它理解成一张敏感度地图。

GPTQ 会用校准数据收集到的输入激活 `X` 构造近似矩阵：

```text
H ≈ X^T X
```

这个矩阵描述了：

- 哪些输入维度经常很活跃。
- 哪些输入维度变化会明显影响输出。
- 哪些输入维度经常一起变化。

如果某个权重量化错一点，但它对应的输入维度经常很大，那么输出误差也会很大。这样的权重就需要小心处理。

反过来，如果某个输入维度几乎不怎么出现，那么对应权重量化粗糙一点，对最终输出影响可能也不大。

## 4. GPTQ 的量化步骤

### 4.1 准备原始模型

原始模型中的线性层权重通常是高精度的：

```text
W: FP16 / BF16
```

例如某一行权重可能是：

```text
[0.137, -0.421, 0.803, 0.052]
```

量化前，这些权重都是连续的浮点数。

### 4.2 收集校准激活

GPTQ 拿一小批普通文本跑一遍模型，例如：

```text
“什么是大语言模型？”
“请解释 Transformer。”
“北京是中国的首都。”
```

模型正常前向推理，不训练、不改参数。GPTQ 只是在每个线性层前面记录它收到的输入数字。

这些记录下来的内部输入就是 `X`。

### 4.3 构造敏感度信息

GPTQ 根据收集到的 `X` 构造近似二阶信息：

```text
H ≈ X^T X
```

通俗理解：

```text
H 是一张表，告诉 GPTQ：
哪些输入维度重要？
哪些输入维度相关？
某个权重量化错了，能不能用其他权重补偿？
```

### 4.4 按列或按块量化权重

GPTQ 不是一次性把整层全部量化，而是按列或按 block 逐步处理。

假设要把下面的 FP16 权重量化成 4-bit：

```text
原始权重:
[0.137, -0.421, 0.803, 0.052]

INT4 编码:
[9, 3, 15, 8]

反量化近似值:
[0.125, -0.400, 0.800, 0.050]
```

量化后模型不会再保存完整 FP16 权重，而是保存：

```text
INT4 权重码 + scale + zero_point + group 信息
```

### 4.5 计算当前量化误差

例如第一个权重：

```text
原权重:     0.137
量化近似:   0.125
误差:       0.012
```

普通量化到这里就结束了。

GPTQ 会继续问：

```text
这个 0.012 会让输出变多少？
能不能让后面还没量化的权重稍微调整一下，把输出补回来？
```

### 4.6 把误差补偿到后续权重

举一个极简例子：

```text
y = w1*x1 + w2*x2
```

原来：

```text
w1 = 0.30
w2 = 0.70
```

如果 `w1` 被量化成：

```text
w1q = 0.25
```

那么 `w1` 少了 `0.05`。

如果校准数据发现 `x1` 和 `x2` 经常差不多，例如都接近 10，那么可以稍微调大 `w2`：

```text
w2: 0.70 -> 0.75
```

输出就可以保持接近：

```text
原输出: 0.30*10 + 0.70*10 = 10
新输出: 0.25*10 + 0.75*10 = 10
```

单看 `w1` 是错了，但整体输出没怎么变。

这就是 GPTQ 的补偿思想：

```text
当前权重量化造成的输出误差，
通过调整后面还没量化的权重来尽量抵消。
```

## 5. 数据在 GPTQ 过程中如何变化

可以按下面的流程理解：

```text
原始模型:
FP16 权重 W
```

进入校准阶段：

```text
FP16 权重 W 不变
收集激活 X
计算 H ≈ X^T X
```

开始量化：

```text
量化第 1 列权重:
W[:, 1] -> INT4 近似值
得到误差 e1
用 H 的信息调整 W[:, 2:]
```

继续量化：

```text
量化第 2 列权重:
此时第 2 列已经不是最原始的权重
而是经过第 1 列误差补偿后的权重
W[:, 2] -> INT4
得到误差 e2
继续调整 W[:, 3:]
```

最终：

```text
大部分 Linear 权重变成 INT4 压缩存储
额外保存 scale / zero_point / group 信息
校准激活 X 被丢弃
H 也被丢弃
```

推理时不会再做 GPTQ 的补偿计算。补偿已经体现在最终量化权重里。

## 6. 什么是输入激活 X

`X` 不是原始文本，也不是训练标签，而是模型内部的一串数字。

例如输入一句话：

```text
“今天天气很好”
```

文本先被切成 token：

```text
["今天", "天气", "很", "好"]
```

每个 token 会变成向量：

```text
“今天” -> [0.12, -0.45, 0.88, ...]
“天气” -> [0.33,  0.09, -0.21, ...]
```

这些向量经过一层又一层 Transformer 后，会变成新的内部表示。

到了某个线性层前，这个线性层即将收到的输入向量，就是 GPTQ 说的输入激活 `X`。

可以用工厂流水线类比：

```text
原始文本 = 原材料
前面几层 Transformer = 前面的加工机器
当前线性层 = 当前机器
X = 送到当前机器入口处的半成品状态
```

GPTQ 收集 `X`，本质上是在问：

```text
模型真实使用时，每一层到底吃到什么样的输入？
在这些真实输入下，哪些权重量化错了会更危险？
哪些误差可以被其他权重补回来？
```

这就是 GPTQ 不需要训练标签的原因。它不关心这句话的正确答案是什么，只关心这句话在模型内部产生了什么样的数字流。

## 7. 如果不同样本的 X 一会大一会小怎么办

不同样本、不同 token 的输入激活确实会波动很大。GPTQ 不是拿单个样本决定量化，而是把很多样本、很多 token 的激活一起统计。

例如某个输入维度在不同 token 上是：

```text
x_i = [0.2, 0.1, 5.8, 0.3, -4.9, 0.2, ...]
```

GPTQ 不会只看某一次大不大，而是看整体统计。近似二阶矩阵里某个对角项可以理解成：

```text
H[i, i] = x_i 在很多样本上的平方累加
```

所以：

```text
0.2^2 + 0.1^2 + 5.8^2 + 0.3^2 + (-4.9)^2 + ...
```

因为平方后都是正数，正负不会互相抵消。某个维度如果偶尔特别大，它仍然会被统计出来，说明这个维度一旦活跃，对输出影响就比较明显。

GPTQ 看的不是：

```text
这个输入这一次大不大？
```

而是：

```text
在一批真实文本里，这个输入维度总体有多活跃？
它大起来的时候会不会严重影响输出？
它和其他输入维度有没有一起变化的规律？
```

因此，校准样本必须尽量有代表性。如果只拿日常对话文本做校准，但模型实际用于代码生成，那么量化结果可能更适合日常对话，不一定最适合代码场景。

实践中通常会：

- 选择和真实使用场景接近的校准数据。
- 使用几十到几百条样本，而不是只用一两条。
- 每层收集大量 token 的激活。
- 加 damping，避免某些异常大值让矩阵不稳定。
- 对敏感层或输出头选择不量化，或者使用更高 bit。

## 8. 推理时模型如何使用量化权重

GPTQ 完成后，推理时通常有两种方式：

```text
方式一:
INT4 权重 -> 临时反量化成 FP16/BF16 -> 做矩阵乘法

方式二:
使用专门 kernel，直接用压缩权重做高效计算
```

所以 GPTQ 是一次性的离线处理：

```text
量化前:  FP16 权重，显存大
量化中:  用校准数据和二阶信息修正误差
量化后:  INT4 权重 + scale，显存小
推理时:  不再需要校准数据
```

## 9. 最关键的理解

GPTQ 的本质不是单纯压缩每一个权重，而是在做一个带补偿的近似：

```text
权重可以变粗糙，
但线性层在真实输入上的输出要尽量不变。
```

一句话总结：

```text
GPTQ 先观察模型真实运行时每层会收到什么样的输入，
再根据这些输入判断哪些权重更敏感，
最后边量化边把误差分摊给还没量化的权重，
让整个线性层的输出尽量接近原模型。
```
